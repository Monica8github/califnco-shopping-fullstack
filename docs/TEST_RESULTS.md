## Test coverage

The 29 tests cover server-selected retail/wholesale prices; dealer approval and minimum order quantities; current roles overriding stale sessions; tampered pricing and malformed quantities/addresses; concurrent inventory reservation; idempotency-key reuse; merged duplicate SKUs; expiry and cancellation stock restoration; payment signature binding; captured amount/currency/order checks; late-payment review; fulfillment transitions; owner restrictions; API 401/403 behavior; service creation; forged webhook rejection; scheduler authentication; draft generation; repeated/concurrent live-job calls with a mock publisher; bounded provider errors; uncertain publication; and prevention of fixture publishing.

The browser sample test disables network fetches and exercises catalogue redaction, customer order/payment simulation, dealer decisions, session persistence and the labeled image example. It also runs without `crypto.randomUUID`, matching ordinary HTTP development origins. The browser walkthrough discovered that compatibility issue; the fix uses `getRandomValues`, and the same checkout then completed successfully.

The three emulator tests create a local Firebase Auth token and exercise API profile persistence, deny direct client promotion/forged orders/wholesale/cross-user access, and allow explicitly bootstrapped administrator reads. Expected `PERMISSION_DENIED` log entries are successful negative assertions. Firebase CLI emitted a Java-version deprecation warning; use Java 21 for future compatibility.

The runtime check was added after an earlier deployment exposed extensionless Node ESM imports. Server imports now use `.js` specifiers, and the check imports the compiled API with ordinary Node to exercise that exact failure class. A source startup check is not a live redeployment claim.

## ZIP validation

`python3 scripts/package-source.py` creates the named source archive, validates required files, parses included JSON, checks at least 50 unique catalogue products and their local images, validates workflow connections, excludes dependency/cache/credential/build files, and verifies every archived byte against `MANIFEST.sha256`. It then reopens the ZIP and checks CRC integrity. Its output provides the final file count, byte size and archive SHA-256. The ZIP milestone is only complete after this command succeeds and the actual download is provided.
